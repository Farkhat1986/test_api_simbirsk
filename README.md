## Установка и запуск проекта

1. Склонировать репозиторий
```
git clone https://github.com/Farkhat1986/test_api_simbirsk.git

"http://localhost:8080"
```
2. Перейти в директорию проекта
3. Создать виртуальное окружение
```
python -m venv venv
```
4. Активировать окружение
```
venv\Scripts\activate
```
5. Установка зависимостей
```
pip install -r requirements.txt
```
6. Запуск тестов
```
pytest --alluredir=allure-results
```
7. Запуск отчета allure по тестам
```
allure serve allure-results
```
# Тест-кейсы для API работы с сущностями

## Создание сущности
**Цель**: Проверить корректное создание новой сущности  
**Предусловия**: Сервер доступен, БД очищена  
**Шаги**:
1. Отправить POST запрос на `/create` с валидными данными
2. Проверить код ответа (201)
3. Проверить, что в ответе получен ID созданной сущности
4. Получить созданную сущность по ID через GET `/get/{id}`
5. Сравнить данные созданной сущности с отправленными  

**Ожидаемый результат**:
- Код ответа 201 Created
- Возвращен ID созданной сущности
- Данные полученной сущности полностью соответствуют отправленным

## Получение сущности по ID
**Цель**: Проверить получение данных конкретной сущности  
**Предусловия**: В системе существует сущность с тестовым ID  
**Шаги**:
1. Отправить GET запрос на `/get/{id}`
2. Проверить код ответа (200)
3. Проверить структуру ответа
4. Проверить типы данных в ответе  

**Ожидаемый результат**:
- Код ответа 200 OK
- Ответ содержит полную информацию о сущности
- Все поля соответствуют ожидаемым типам данных

## Получение списка всех сущностей
**Цель**: Проверить получение полного списка сущностей  
**Предусловия**: В системе существует несколько тестовых сущностей  
**Шаги**:
1. Отправить GET запрос на `/getAll`
2. Проверить код ответа (200)
3. Проверить что ответ является массивом
4. Проверить что количество элементов соответствует ожидаемому  

**Ожидаемый результат**:
- Код ответа 200 OK
- Ответ содержит массив сущностей
- Количество элементов соответствует количеству созданных сущностей

## Обновление сущности
**Цель**: Проверить обновление данных сущности  
**Предусловия**: В системе существует сущность с тестовым ID  
**Шаги**:
1. Отправить PATCH запрос на `/patch/{id}` с новыми данными
2. Проверить код ответа (204)
3. Получить обновленную сущность через GET `/get/{id}`
4. Сравнить данные с отправленными на обновление  

**Ожидаемый результат**:
- Код ответа 204 No Content
- Данные сущности успешно обновились
- Все измененные поля соответствуют новым значениям

## Удаление сущности
**Цель**: Проверить удаление сущности  
**Предусловия**: В системе существует сущность с тестовым ID  
**Шаги**:
1. Отправить DELETE запрос на `/delete/{id}`
2. Проверить код ответа (204)
3. Попытаться получить удаленную сущность через GET `/get/{id}`
4. Проверить код ответа (404)  

**Ожидаемый результат**:
- Код ответа 204 No Content при удалении
- Код ответа 404 Not Found при попытке получения
- Сущность отсутствует в списке всех сущностей

## Валидация входных данных
**Цель**: Проверить обработку невалидных данных  
**Предусловия**: Сервер доступен  
**Шаги**:
1. Отправить POST запрос на `/create` с:
   - Пустым телом
   - Неполными данными
   - Неправильными типами данных
   - Числами вне допустимого диапазона (0-100)
2. Проверить коды ответов (400)  

**Ожидаемый результат**:
- Код ответа 400 Bad Request для всех невалидных запросов
- Ответ содержит информацию об ошибках валидации

## Обработка несуществующей сущности
**Цель**: Проверить обработку запросов к несуществующей сущности  
**Предусловия**: Сервер доступен  
**Шаги**:
1. Отправить GET запрос на `/get/999999` (несуществующий ID)
2. Отправить PATCH запрос на `/patch/999999`
3. Отправить DELETE запрос на `/delete/999999`
4. Проверить коды ответов (404)  

**Ожидаемый результат**:
- Код ответа 404 Not Found для всех операций
- Соответствующие сообщения об ошибках
